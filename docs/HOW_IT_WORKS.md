# 영차 구조와 작동 방식

영차는 친구들의 음료를 모아서 총무가 카페에 한 번에 주문하는 사이트입니다. 수령은 매장에서 하고 결제도 매장에서 합니다.

## 1. 첫 화면과 내정보

첫 화면 가운데에는 ‘먹고 싶은거 다 골라!’와 주문하기 버튼이 있습니다.

로그인 전에는 오른쪽 위에 로그인 버튼이 있습니다. 누르면 카카오톡 로그인 창이 열립니다. 주문 내역은 보이지 않습니다.

로그인 후에는 같은 자리가 내정보로 바뀝니다. 내정보를 누르면 연결된 카카오톡 계정, 영차 닉네임, 내 주문 내역 버튼이 보입니다. 로그아웃도 이 창에서 합니다.

카카오가 제공한 계정 이름이나 확인된 이메일을 사용합니다. 둘 다 없으면 카카오가 알려준 계정 번호로 구분합니다. 이메일을 받으려고 참여자에게 추가 절차를 요구하지 않습니다. 실제로 연결한 카카오 계정이 없으면 ‘연결된 계정 없음’이라고 표시합니다. 영차 닉네임과 카카오 계정 이름은 서로 다른 값입니다.

처음 로그인한 총무는 영차 닉네임을 정합니다. 정한 뒤 원래 보던 화면으로 돌아갑니다. 닉네임은 2~20자이며 다른 사람과 겹칠 수 없습니다. 현재는 정한 닉네임을 바꾸는 기능이 없습니다.

## 2. 누가 무엇을 할 수 있나

| 이용자 | 들어오는 방법 | 하는 일 |
|---|---|---|
| 총무 | 카카오 로그인 | 카페 선택, 주문방 생성, 취합, 수량 수정·삭제, 마감, 전송, 접수 전 취소 |
| 친구·참여자 | 공유 링크, 로그인 없음 | 메뉴·옵션·수량과 이름을 입력하고 제출 |
| 판매자 | 발급받은 계정 | 자기 매장에 전송된 주문의 수락·거절·준비 완료 |
| 운영자 | 운영자 계정 | 매장·메뉴·판매자 관리, 전체 주문·이력 조회 |

판매자와 운영자 로그인은 첫 화면 하단의 작은 링크로 들어갑니다. 판매자·운영자의 내정보에는 카카오 대신 발급 계정이 표시됩니다. 각자에게 맞는 주문 화면으로 연결됩니다.

## 3. 주문이 진행되는 순서

1. 총무가 카페를 고르고 주문방을 만듭니다. 이때부터 주문방이 저장됩니다.
2. 참여 링크를 카카오톡 단체방에 직접 보냅니다.
3. 친구들은 링크에서 여러 음료를 담고 이름을 적어 제출합니다. 총무의 음료도 같은 링크에서 담습니다.
4. 총무가 전체 내역을 확인합니다. 필요한 항목을 삭제하거나 수량을 조절합니다.
5. 마감하면 친구들의 추가 제출이 막힙니다. 다시 열 수 없습니다. 총무의 수량 정리는 아직 가능합니다.
6. 최종 전송하면 카페가 주문을 보게 됩니다. 이때부터 음료 내역을 바꿀 수 없습니다.
7. 카페가 준비 시간을 입력하고 수락합니다. 총무 화면에는 완성 예정 시각이 보입니다.
8. 준비 완료를 누르면 총무에게 표시됩니다. 매장에서 음료를 받고 결제합니다.

카페를 구경하는 데 로그인은 필요 없습니다. 총무가 주문방을 만들 때는 로그인이 필요합니다. 로그인과 닉네임 설정 뒤에는 원래 고르던 카페로 돌아갑니다.

## 4. 주문 상태에 따라 가능한 일이 달라진다

| 상태 | 가능한 일 |
|---|---|
| 모집 중 | 친구 제출, 총무 삭제·수량 조절·마감 |
| 마감 | 총무 삭제·수량 조절·최종 전송 |
| 접수 대기 | 판매자 수락·거절, 총무 전체 취소, 5분 미접수 자동 취소 |
| 준비 중 | 판매자 준비 완료 |
| 준비 완료·취소·거절 | 기록 조회 |

판매자가 수락하면 총무가 취소할 수 없습니다. 취소·거절로 끝난 주문을 다시 보내거나 재개할 수 없습니다. 다시 주문하려면 새 주문방을 만듭니다. 모집 중·마감 방을 폐기하는 정책은 아직 정하지 않았습니다.

## 5. 화면과 주문 기록은 어떻게 연결되나

화면은 버튼과 메뉴를 보여줍니다. 처리 컴퓨터인 ‘서버’는 권한과 주문 상태를 확인하고 금액을 계산합니다. 저장 공간인 ‘DB’는 주문과 변경 기록을 보관합니다.

총무·친구·판매자·운영자의 화면은 같은 주문 기록을 봅니다. 역할마다 별도의 원본 주문을 만들지 않습니다. 그래서 한쪽에서 저장한 결과를 다른 쪽에서도 확인할 수 있습니다.

사이트는 Django라는 제작 도구로 만들었습니다. 기록은 SQLite라는 실제 파일 저장소에 넣습니다. 처음에는 한 컴퓨터에서 사이트와 저장소를 관리하는 구성이며, 여러 서버로 늘리는 구성은 별도 검토가 필요합니다.

저장하는 것은 계정·역할·닉네임, 매장·메뉴·옵션, 주문방, 참여자의 최초 제출, 총무가 정리한 내역, 금액·시각·처리 이력입니다. 카카오 비밀번호를 받아 저장하는 방식이 아닙니다.

## 6. 금액과 변경 기록

항목 금액은 ‘음료 기본 가격 + 선택 옵션 추가 금액’에 수량을 곱합니다. 같은 음료라도 옵션이 다르면 따로 집계합니다. 서버가 직접 계산하며 화면이 보낸 합계를 그대로 믿지 않습니다.

예를 들어 라떼 4,500원에 샷 추가 500원을 선택해 두 잔을 담으면 10,000원입니다.

주문방을 만들 때의 메뉴·가격을 보관합니다. 나중에 카페가 가격을 바꾸더라도 이미 만든 방의 가격과 과거 주문 금액은 바뀌지 않습니다.

총무가 수량을 줄이거나 항목을 삭제해도 최초 제출 내역은 남습니다. 누가 언제 무엇을 바꿨는지도 남습니다. 화면에는 정리된 최종 수량과 금액이 표시됩니다. 수량은 항목당 1~99잔이며 삭제는 유효 수량 0으로 처리합니다. 모든 항목을 삭제한 빈 주문은 전송할 수 없습니다.

## 7. 5분 자동 취소

5분은 주문서 전송이 정상 저장된 시각부터 셉니다. 새로고침해도 다시 시작하지 않습니다.

브라우저와 별도로 계속 실행하는 취소 작업이 있습니다. 이 작업이 보통 1초마다 접수 기한을 확인합니다. 따라서 친구들과 총무가 화면을 모두 닫아도 취소 처리가 가능합니다.

5분이 지난 주문은 판매자가 수락할 수 없습니다. 취소 작업이 조금 늦더라도 수락 요청 자체에서 시간을 다시 확인합니다. 이미 수락한 주문은 이 5분 규칙으로 취소하지 않습니다. 서버가 꺼져 있는 동안에는 작업도 멈추므로 실제 운영에서는 자동 재시작 설정이 필요합니다.

## 8. 여러 사람이 동시에 누르거나 인터넷이 끊기면

같은 주문에 동시에 들어온 변경을 한 번에 섞어 저장하지 않습니다. 권한·상태·내용을 함께 확인하고 일관된 한 결과를 저장합니다.

예를 들어 총무의 취소와 판매자의 수락이 겹치면 둘 중 먼저 정상 확정된 하나만 인정합니다. 마감 후에 뒤늦게 들어온 참여 제출은 거절합니다. 총무의 수정과 전송이 겹치면 오래된 내용을 그대로 보내지 않고 최신 내역 확인을 요구합니다.

각 제출·전송 요청에는 구별용 번호를 붙입니다. 같은 요청을 다시 보내면 기존 결과를 확인합니다. 서버는 저장했지만 답변이 끊긴 경우에도 중복 제출·중복 전송을 막습니다. 서로 다른 요청으로 같은 이름이 다시 제출된 것은 임의로 합치지 않습니다.

## 9. 화면 갱신과 알림

진행 화면은 보통 3초마다 저장된 최신 내용을 다시 확인합니다. 인터넷이 끊기면 연결이 끊겼다고 표시합니다. 다시 연결하면 현재 상태를 다시 읽습니다. 연결 상태나 브라우저 상황에 따라 갱신이 늦을 수 있습니다.

판매자에게 새 주문이 있으면 페이지 안에 알림을 띄웁니다. 소리를 켜는 버튼을 눌러 활성화하면 대기 주문이 남아 있는 동안 반복해서 소리를 냅니다. 한 건을 처리해도 다른 대기 주문의 알림은 유지됩니다.

총무에게는 준비 완료를 화면에서 알려줍니다. 판매자처럼 반복 소리를 내지는 않습니다. 앱을 닫거나 기기가 잠든 상태의 알림, 문자·알림톡·휴대폰 푸시는 이번 기능에 포함되지 않습니다.

## 10. 권한과 이름의 한계

버튼을 숨기는 것만으로 보호하지 않습니다. 서버도 로그인 계정·역할·주문 소유자·매장을 검사합니다. 주소의 주문 번호나 매장 번호를 바꿔도 다른 사람의 자료를 볼 수 없게 합니다. 내정보도 로그인한 본인의 계정만 조회합니다.

친구에게 공유한 링크는 총무의 관리 권한을 주지 않습니다. 참여자는 다른 사람의 상세 주문을 볼 수 없습니다. 제출 후에는 본인도 수정·삭제할 수 없습니다.

참여자가 입력한 이름은 본인 인증이 아닙니다. 링크는 다른 사람에게 다시 공유될 수 있습니다. 허위 주문을 자동으로 알아내는 기능은 없습니다. 총무가 확인하고 전송 전에 삭제·수량 조절로 정리합니다.

## 11. 판매자 삭제와 기록 보존

운영자가 판매자를 삭제하면 해당 계정의 접근이 막힙니다. 해당 매장을 새로 선택하거나 기존 방에서 새 주문서를 보내는 것도 막힙니다.

접수 대기·준비 중 주문은 판매자 삭제에 따른 취소로 기록합니다. 주문과 매장 정보를 통째로 지우지는 않습니다. 이전 내역과 처리 이력은 총무와 운영자가 계속 확인할 수 있습니다.

## 12. 지금 확인한 것과 아직 남은 것

확인한 것: 실제 저장소를 사용하는 주문 흐름, 역할별 접근 제한, 합계, 중복 요청 방지, 동시 요청, 5분 경계, 실제 5분 대기 후 자동 취소, 기록 백업과 별도 복원, PC·휴대폰 크기 화면, 로그인·내정보 화면 전환.

현재는 시험용 매장과 계정을 사용합니다. 독립된 브라우저 화면끼리 같은 기록을 보는 것은 시험했지만 실제 여러 휴대폰에서의 사용은 아직입니다. 카카오 연결 코드는 있으나 카카오 앱·키가 없어 실제 카카오 로그인은 시험하지 못했습니다. 시연 계정에는 카카오 연결이 없다고 표시합니다.

공개하려면 카카오 앱 연결, 실제 매장·메뉴 등록, 인터넷 주소와 사이트를 운영할 컴퓨터 준비, 실제 휴대폰·카페 스피커 시험이 필요합니다. 영업 종료 시 주문 규칙과 개인정보를 얼마나 보관하고 어떻게 지울지도 정해야 합니다. 유료 서비스 계약이나 공개 배포는 아직 하지 않았습니다.

설치·실행 안내, 사용 도구의 근거, 승인된 정책, 주문 저장 구조, 시험 결과, 카카오 설정, 계정 발급, 백업·복원 방법을 문서로 남겼습니다. 다른 개발자가 이어서 관리할 수 있도록 코드와 필요한 도구의 버전도 함께 보관했습니다.
