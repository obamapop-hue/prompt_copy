# 인수 시험 기록

실행일: 2026-10-12. 로컬 클라우드 Linux, Python 3.12.14, Django 5.2.18, SQLite 3.53.1 실제 파일 DB, Chromium, Playwright 1.62.1. 시연 데이터만 사용. 모든 역할이 같은 DB를 조회한다.

자동 시험: `manage.py test orders --noinput` **40개 통과, 실패 0, 건너뜀 0**. 동시성 시험은 SQLite 파일 DB와 별도 스레드·별도 DB 연결을 사용했다. 공유 메모리 DB로 대체하지 않았다.

브라우저: `npm run test:browser`, `npm run test:alerts` 통과. 독립 브라우저 context 4개, 모바일 390px와 데스크톱 1440px. 총무 세션만 `prepare_browser_test` 시험용 Django 인증을 사용했다. 판매자·운영자는 실제 발급 계정·Django 비밀번호 인증. 참여자는 익명.

추가 통과: CSRF 차단, 로그인 5분 내 시도 제한, capability URL 로그 가림, 요청 내용이 다른 idempotency key 재사용 충돌, 기간·상태·주문번호·20건 페이지 조회, 운영자 화면 등록 API 내용이 실제 카페 목록·메뉴로 반영.

환경 검증: 설치 스크립트 재실행 시 기존 DB·키·시연 계정 유지. 마이그레이션 누락 없음, Django check 오류 없음, pip check 충돌 없음. pip-audit 알려진 취약점 발견 없음. 실제 DB online backup 후 별도 파일 복원 integrity·foreign key·전체 테이블 행 수 일치. Gunicorn 26.2.0 WSGI 2 workers에서 홈페이지와 DB 카페 조회 HTTP 성공.

운영 설정 `check --deploy`는 HSTS subdomain/preload 관련 경고 2개. 대표 도메인·하위 도메인 정책 미정으로 해당 기능을 임의 활성화하지 않음. DEBUG 개발 설정의 HTTPS 관련 경고는 운영 준비 완료 증거로 취급하지 않음.

## 남은 인수 조건

T01·T02·T14·T17의 실제 기기·Kakao 시험, 실제 HTTPS 배포·영속 디스크·worker 자동 재시작·오프호스트 백업 복원, 공개 전 개인정보·영업 정책 확정. 지금 결과는 로컬 개발 기능 검증이며 실제 카카오 연동·공개 운영 완료를 뜻하지 않는다. 배포 비용 발생·서비스 공개는 수행하지 않았다.

## 영차 화면 수정 확인 (2026-10-12)

메인 화면은 로그인·주문하기·내 주문 목록 세 가지로 변경했다. 로그인 팝업과 카카오톡 로그인 버튼, 영차 제목, 빨간색 테마, PC·휴대폰 크기에서 가로 넘침 없음 확인. 브라우저 주문 흐름 시험은 새 화면에 맞춰 재실행했고 통과했다. 카카오 실제 로그인은 계속 미실행이다.
