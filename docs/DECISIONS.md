# 결정 기록

## 2026-10-12 — 킹갓진홍 승인

사용자는 제안한 정책에 동의하면서 판매자 삭제 정책을 다음과 같이 지정했다.
“진행 주문 여부에 상관 없이 삭제할 수 있도록 해. db에는 판매자 삭제로 주문 취소 처리로 기록을 남겨.”

- 닉네임: 최초 설정 후 변경 불가, NFC 정규화, 앞뒤 공백 제거. 2~20자 한글 완성형·영문·숫자·밑줄. 영문 대소문자 무시한 DB 고유 제약.
- 매장 메뉴·가격: 주문방 생성 시 스냅샷. 모집 중 메뉴 변경은 기존 방에 반영하지 않는다. 총무·참여 화면에 생성 시점 가격임을 표시한다.
- 수락: SQLite IMMEDIATE 트랜잭션에서 읽은 DB 시각이 기한보다 엄격히 이전일 때만 허용. 같거나 늦으면 자동 취소를 확정한다. 서버 수신·사용자 클릭 시각 우선 규칙은 없다.
- 기한 전 동시 취소·수락·거절은 먼저 유효하게 확정된 상태 전이 하나만 인정한다.
- 수량: 항목당 1~99잔. 총무 삭제는 유효 수량 0과 삭제 표시로 처리. 이름: NFC 정규화·양끝 공백 제거 후 1~30자. 준비 시간: 1~180분.
- 화면 조회 3초 간격, 자동 취소 서버 작업 1초 간격. 장애·DB 대기·부하 중에는 지연될 수 있다. 수락 API 자체의 만료 검사는 작업 지연과 관계없이 적용한다.
- 판매자 삭제: 계정·연결을 물리 삭제하지 않고 비활성화. 사용자도 비활성화하여 기존 로그인 세션 요청을 차단한다. 매장은 신규 선택·전송 불가. 해당 매장 PENDING·ACCEPTED 주문은 SELLER_DELETED 상태, 처리 주체 운영자, seller_deleted 이력을 기록한다. 이미 기한이 지난 PENDING은 AUTO_CANCELLED로 기록한다. 모집 중·마감 방은 유지하되 전송이 불가하다. 종료 주문은 유지한다. 삭제 대상 외에 같은 매장에 연결된 계정이 있다면 그 계정의 과거 이력 조회 권한은 유지된다.
- 총무 준비 완료 알림은 페이지 내 배너·일회성 토스트이며 소리는 사용하지 않는다. 판매자 소리는 사용자 동작으로 활성화 후 4초 간격, 대기 주문이 있을 때만 재생한다.
- 서비스명은 영차로 확정했다.

## 아직 결정하지 않은 공개 전 운영 정책

영업 종료 시 주문 허용, 모집 중·마감 방 폐기, 개인정보 보관 기간·삭제 절차, 실제 제휴 매장·메뉴, 서비스명·로고·도메인, 호스팅 및 유료 비용.
미결정 기능은 추가하지 않았다. 현재 공개 배포는 하지 않았다.

## 기술 결정

Django 5.2 LTS + django-allauth + 실제 SQLite DB + 단일 호스트. 별도 expire_orders 프로세스, 3초 폴링. SQLite는 트랜잭션을 지원하고 모든 업무 변경을 짧은 IMMEDIATE 트랜잭션으로 직렬화한다. 멀티 호스트·네트워크 파일시스템 배포는 지원하지 않는다. 그 구성이 필요하면 PostgreSQL 이전과 비용을 협의해야 한다.

Gunicorn 버전 선정 중 공식 SECURITY.md에서 23.0.0 지원 종료를 확인했다. 최종 선택은 지원되는 26 계열의 안정 릴리스 26.2.0이다. 실험 기능 HTTP/2·dirty arbiter·ASGI는 사용하지 않는다. 최종 잠금 파일과 기술 선정표에 반영했다.

## 2026-10-12 — 영차 이름·화면 변경 승인

사용자 지시: 서비스명은 **영차**. 메인은 로그인(카카오 로그인 팝업)·주문하기·내 주문 목록 3개로 단순화. 홍보·소개 문구와 첫 화면 카페 목록 제거. 흰 배경·가는 경계·검은 글씨에 빨간 강조색으로 변경. 판매자·운영자 진입은 기존 합의대로 하단 작은 링크 유지. 실제 데이터와 시연을 구별하기 위한 ‘시연’ 표시는 작은 배지로 유지.

블라인드 공식 사이트는 클라우드에서 접속 403으로 실제 화면 열람 불가. 로고·코드·자산은 복제하지 않았으며 위 시각 요소로 사용자 요청의 방향을 적용했다. 카카오 실제 앱 연결 전에는 팝업에 로그인 버튼과 준비 중 표시를 제공하고 로그인 성공을 가장하지 않는다.

사용자 설명은 전문용어 없이 짧고 쉬운 한국어로 제공한다. 이전 기록의 가칭은 현재 영차로 확정되었다.

## 2026-10-12 — 로그인·내정보·첫 화면 배치 변경

사용자 승인: 로그인 버튼은 우측 상단. 메인에는 ‘먹고 싶은거 다 골라!’와 그 아래 주문하기. 로그인 전에는 내 주문 목록을 표시하지 않음. 로그인 후 동일 위치를 내정보로 교체. 내정보에는 실제 연결된 카카오 계정·가입 시 정한 영차 닉네임·내 주문 내역 버튼을 표시. 로그아웃도 내정보 안으로 이동.

카카오가 제공한 실제 프로필·확인된 이메일·계정 식별자만 사용한다. 추가 이메일 동의 요구는 도입하지 않는다. 미연결 시연 계정에는 연결 없음으로 표시. 내정보 조회는 서버에서 로그인한 본인만 허용한다. 판매자·운영자는 발급 계정과 각자의 주문 기록 화면을 사용한다.

첫 로그인 닉네임 설정 후 원래 화면으로 복귀. 메인에서 로그인한 경우 메인으로 복귀한다. 참여 링크에는 닉네임 설정·로그인 요구를 추가하지 않는다.
